# Languages (i18n)

The main site is available in **seven languages**: English (`en`), Croatian
(`hr`), German (`de`), Spanish (`es`), Italian (`it`), Chinese (`zh`) and
Japanese (`ja`). Translation runs entirely in the browser: the English text in
the HTML is the source, and small dictionary files swap it out at runtime. There
is no build step and no server.

Privacy-policy pages (`privacy-policies/`) are standalone and are **not**
translated.

## Files

| File | Loaded | Role |
|---|---|---|
| `assets/i18n/boot.js` | sync, in `<head>` right after `theme.js` | Picks the language before the first paint, sets `<html lang>`, starts loading the dictionary. Holds the `SUPPORTED` list. |
| `assets/i18n/i18n.js` | `defer`, right after `components.js` | Applies translations, switches language at runtime, renders `<lang-switch>`, exposes `bearvilT()`. Holds `LANG_NAMES`. |
| `assets/i18n/<lang>.js` | injected on demand | One dictionary per non-English language (`hr`, `de`, `es`, `it`, `zh`, `ja`), 123 keys each. |

Every main page loads the scripts in this order:

```html
<!-- Theme + language: set <html data-theme> / <html lang> before first paint (sync, first) -->
<script src="/assets/theme.js"></script>
<script src="/assets/i18n/boot.js"></script>
…fonts, stylesheets…
<script src="/assets/components.js" defer></script>
<script src="/assets/i18n/i18n.js" defer></script>
```

All of them are same-origin files, so the CSP (`script-src 'self'`) needs no
change.

## How it works

### 1. Picking the language (`boot.js`)

Order of precedence:

1. the visitor's stored choice — `localStorage` key `bearvil-lang`
   (written by the language menu);
2. the first entry of `navigator.languages` whose base code (`de-AT` → `de`) is
   supported;
3. otherwise `en`.

`boot.js` sets `<html lang="…">` and `window.BEARVIL_LANGS` (the supported
list). Then:

- **English:** nothing to load; `window.BEARVIL_I18N_READY` is an already
  resolved promise.
- **Any other language:** it adds `html.i18n-pending`, which hides the body
  (`.i18n-pending body { visibility: hidden; }` in `base.css`) so visitors never
  see English flash before the translation. It injects
  `/assets/i18n/<lang>.js` immediately and exposes the load as the promise
  `window.BEARVIL_I18N_READY`. A **2.5 s safety timer** removes
  `i18n-pending` regardless, and a failed load reveals the page in English, so
  the page is never left hidden.

### 2. Applying translations (`i18n.js`)

When `BEARVIL_I18N_READY` resolves, `i18n.js` runs
`applyTranslations(lang)`, syncs the language menu, and removes
`i18n-pending`.

`applyTranslations` handles two markup hooks:

| Markup | Effect |
|---|---|
| `data-i18n="key"` | Replaces the element's **`innerHTML`** with the dictionary value. |
| `data-i18n-attr="attr:key;attr2:key2"` | Sets one or more **attributes** from the dictionary (e.g. `content` on the meta description, `aria-label`, `data-copied-label`). |

On its first pass it caches the English original in `data-i18n-en` (text) and
`data-i18n-en<Attr>` (attributes, e.g. `data-i18n-en-content`), so switching back
to English needs no reload. A key missing from a dictionary falls back to the
English text. A `<title data-i18n>` also updates `document.title`.

### 3. Switching at runtime

`setLanguage(lang)` stores the choice in `bearvil-lang`, loads the dictionary if
it isn't loaded yet, sets `<html lang>`, re-applies translations and syncs every
`<lang-switch>`. No page reload.

### 4. Strings built in JavaScript

Text that `components.js` generates carries the same hooks: nav, footer and
mobile-menu labels use `data-i18n` (`nav.home`, `nav.work`, `nav.about`,
`nav.contact`, `nav.privacy`), and the hamburger uses
`data-i18n-attr="aria-label:nav.menu"`. Labels that are computed in code use
`bearvilT(key, fallback)` — it returns the current language's value, or the
fallback for English or a missing key. The theme toggle's label
(`theme.toDark` / `theme.toLight`) works this way; `applyTranslations` re-runs
`syncThemeToggle` so it updates on a language switch.

### 5. The language menu — `<lang-switch>`

A custom element defined in `i18n.js` and rendered by `<top-nav>` inside
`.topnav-actions` (before the theme toggle). It shows a globe icon plus the
current code (`EN`, `HR`, …); the list shows each language in its native name
(`LANG_NAMES`), with `lang` set on each option and `aria-current` plus a check
mark on the active one. Click toggles it; choosing a language, `Escape` or an
outside click closes it. The toggle's `aria-label`/`title` is translated via
`nav.language`. Styles: `components.css` (*LANGUAGE MENU*).

### 6. Typography per language

- `tokens.css` overrides `--font-sans` under `:root:lang(zh)` and
  `:root:lang(ja)` with native CJK system font stacks (Inter has no CJK glyphs;
  Latin words still use Inter).
- `base.css`: `<em>` accents stay upright in Chinese and Japanese (no true
  italics); Japanese uses `word-break: auto-phrase` so lines break at phrase
  boundaries (Chromium); all headings use `text-wrap: balance` for even line
  lengths in every language.

## Dictionaries

```js
/* German (de) — Bearvil site translations. … */
(window.BEARVIL_I18N = window.BEARVIL_I18N || {}).de = {
  "home.title": "…",
  …
};
```

- Keys are namespaced by page or area: `home.*`, `work.*`, `about.*`,
  `contact.*`, `notFound.*`, `app.*` (shared app metadata), `common.*` (shared
  buttons such as `common.getInTouch`), `nav.*`, `theme.*`.
- Values are HTML. Keep the **same tags** as the English source (`<em>`,
  `<a href>`, `<span aria-hidden="true">→</span>`, `&nbsp;`), since the value
  replaces `innerHTML`.
- All six dictionaries must have the **same set of keys** (123 today).
- English has no dictionary: the HTML (and the labels in `components.js`) is the
  English source.

## Adding a translatable string

1. In the HTML, give the element a key with the English text as its content:

   ```html
   <p class="section-head__sub" data-i18n="work.newNote">Both apps are free.</p>
   ```

   For an attribute, use `data-i18n-attr`:

   ```html
   <meta name="description" content="…" data-i18n-attr="content:press.metaDesc" />
   ```

2. Add the key to **all six** dictionaries (`hr`, `de`, `es`, `it`, `zh`, `ja`),
   keeping the HTML tags identical to the English.
3. Check that every file still has the same key count:

   ```sh
   for l in hr de es it zh ja; do printf "%s " $l; grep -c '^  "' assets/i18n/$l.js; done
   ```

4. For a string built in JavaScript, either emit `data-i18n` on the generated
   element (like the nav links) or use `bearvilT('key', 'English fallback')`.

Reuse an existing `common.*` key when the text is the same (e.g. "Get in touch").

## Adding a language

1. **`boot.js`** — add the code to `SUPPORTED`.
2. **`i18n.js`** — add the code and its native name to `LANG_NAMES`
   (e.g. `fr: 'Français'`).
3. **Dictionary** — create `assets/i18n/<code>.js` by copying an existing one,
   changing the language code on the `window.BEARVIL_I18N.<code>` line, and
   translating every value.
4. **Fonts** — if the script isn't covered by Inter (e.g. Korean, Arabic), add a
   `:root:lang(<code>)` block in `tokens.css` with a native system font stack,
   and check `base.css` for language-specific rules (italics, line breaking). A
   right-to-left language would also need `dir` handling, which the site does not
   have yet.
5. Test it: pick the language in the menu, reload (the choice must persist with
   no English flash), and check the nav, the mobile menu and every page.

## SEO and limitations

- **Only English is indexed.** Translation happens client-side, so crawlers and
  social previews see the English HTML. There are no per-language URLs and no
  `hreflang` tags; `og:*` tags are not translated.
- Without JavaScript the site stays in English (and `boot.js` never hides it).
- The app names, privacy-policy link labels and the email address are not
  translated.
- The styleguide has no `data-i18n` hooks; only its nav and footer translate.
